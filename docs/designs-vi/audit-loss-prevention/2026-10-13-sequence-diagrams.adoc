== Phạm vi và Quy ước ký hiệu (Scope & Notation)

Các sơ đồ này là các biểu đồ thiết kế (design-level diagrams) được sinh ra sau khi người dùng đã xác nhận 8 luồng nghiệp vụ và ranh giới các bên tham gia. Repository hiện chưa có mã nguồn triển khai ứng dụng; tên component, hàng đợi và endpoint phản ánh chính xác tài liệu Hợp đồng (Contracts) và Kiến trúc (Architecture), không phải là trace từ mã nguồn lúc chạy thực tế.

* L1: Luồng cấp độ hệ thống giữa các tác nhân, service, message broker, database và kho lưu trữ object storage.
* L2: Luồng nội bộ backend; Repository/DAO được thu gọn vào ranh giới Service → DB.
* Các dữ kiện doanh thu `OrderPaid`/Payment không được Audit tự ý suy diễn; Audit chỉ tiêu thụ các dữ kiện nguồn đã được phê duyệt.
* Audit & Loss Prevention tuyệt đối không chặn các thao tác của Order, Payment, Shift hay POS.

== Các Bên Tham Gia (Participants)

Cấp L1 sử dụng các bên tham gia đã được xác nhận: Owner/Manager/Cashier, Angular/POS, Order, Promotion, Payment, Shift/POS Device, Identity, EventBridge/SQS, Audit, PostgreSQL, Loss Worker, Case Service và kho lưu trữ Encrypted Object Storage.

=== 1.1 L1 — Luồng Hệ Thống (System Flow)

[plantuml]
----
@startuml
!theme toy

title Order cancel → Audit evidence — L1: System Flow

actor "Manager/POS" as actor
participant "Order Service" as order
queue "EventBridge/SQS" as bus
participant "Audit Service" as audit
database "Audit PostgreSQL" as db

actor -> order: [HTTP/REST] POST /api/v1/orders/{id}/lines/{lineId}/cancel
order -> order: Kiểm tra quyền, lý do, If-Match và phạm vi đơn hàng
alt Phạm vi / trạng thái / lý do không hợp lệ
  order --> actor: Trả lỗi an toàn HTTP 403/409/422
else Hủy hợp lệ
  order -> order: Commit trạng thái dòng món + outbox OrderLineCancelled.v1
  order ->> bus: [EventBridge/SQS] OrderLineCancelled.v1
  bus ->> audit: [SQS async] phân phối sự kiện
  audit -> audit: Xác thực, làm sạch dữ liệu và khử trùng sourceEventId
  audit -> db: INSERT bằng chứng kiểm toán bất biến + projection
  db --> audit: commit bằng chứng / watermark
  audit --> actor: Lệnh nguồn đã trả về thành công trước đó
end

alt Consumer Audit retry / gửi vào DLQ
  audit ->> bus: [SQS async] retry rồi chuyển vào DLQ sau số lần thử có hạn
end
@enduml
----

alt Xác thực thất bại
  orderSvc --> orderSvc: Trả lỗi nghiệp vụ an toàn
else Xác thực thành công
  orderSvc -> orderDb: Transaction: hủy dòng món + cập nhật phiên bản trạng thái
  orderDb --> orderSvc: trạng thái đơn hàng đã commit

  outbox --> orderSvc: ID outbox bền vững

consumer -> validator: Xác thực phong bì / phiên bản / làm sạch dữ liệu
alt Schema không hợp lệ hoặc payload nhạy cảm
  validator --> consumer: Cách ly kiểm dịch / lỗi DLQ an toàn

  consumer -> auditDb: INSERT inbox / khử trùng nguồn
  auditDb --> consumer: sự kiện mới / trùng lặp

    consumer -> auditDb: INSERT audit_events + projection + watermark
    auditDb --> consumer: bằng chứng đã commit
  else Sự kiện nguồn trùng lặp
    consumer --> consumer: Bỏ qua (no-op) tác động projection
  end
end

  digest -> db: INSERT phát hiện toàn vẹn + đóng băng kết quả xác minh
  digest -> alert: [HTTP/REST] Cảnh báo phát hiện lệch digest toàn vẹn
  digest -> audit: [Nội bộ] Ghi nhận AuditIntegrityMismatchDetected.v1
  digest --> ops: MISMATCH + yêu cầu điều tra hạn chế
end

participant "Integrity Finding Writer" as finding
queue "Audit Outbox" as outbox

ctrl -> digestSvc: xin giữ lease xác minh lô
digestSvc -> db: SELECT metadata lô + danh sách ID sự kiện có sắp xếp
db --> digestSvc: thông tin lô
digestSvc -> canon: tuần tự hóa các trường sự kiện chuẩn tắc / phiên bản
canon --> digestSvc: chuỗi byte chuẩn tắc
digestSvc -> digestSvc: Tính toán SHA-256 + previousDigest
digestSvc -> db: INSERT kết quả xác minh
alt Khớp
  db --> digestSvc: VERIFIED
else Không khớp
  digestSvc -> finding: createIntegrityFinding(batch)
  finding -> db: INSERT phát hiện toàn vẹn bất biến
  finding ->> outbox: phát hành AuditIntegrityMismatchDetected.v1
end
@enduml
