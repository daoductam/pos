== Scope and traceability

Các sơ đồ dưới đây là **contract-driven design diagrams**. Repository chưa có AI Assistant/Reporting implementation source, nên participant/message được lấy từ Requirements và Architecture đã được user xác nhận; đây chưa phải runtime trace.

* L1 biểu diễn system-level communication.
* L2 biểu diễn component-level flow trong AI Assistant; repository/DAO được collapse vào database boundary.
* Chat chỉ dùng read-only Reporting tools; Order/Payment/Inventory/Loyalty/Catalog không nằm trên mutation path.
* DeepSeek không được nhận PII/raw transaction identity; Reporting là metric authority.

participant "Reporting Service" as rep
database "AI Assistant PostgreSQL" as db

ui -> ai: [HTTP/REST] POST turn
ai -> id: [HTTP/REST] Resolve requested branch + ai:report:read

alt Branch ngoài membership
  id --> ai: HTTP 200 allowed=false / scope_not_allowed
  ai -> db: Persist refusal + redacted scope summary
  ai ->> bus: [EventBridge async] AIAccessRefused.v1
  ai --> ui: HTTP 403 NEEDS_SCOPE/scope_not_allowed

  id --> ai: HTTP 200 allow + ResolvedScope
  ai -> llm: [HTTP/REST] Redacted question + fixed policy
  llm --> ai: Request SQL/system prompt/scope escalation
  ai -> db: Persist policy refusal
  ai ->> bus: [EventBridge async] AIAccessRefused.v1
  ai --> ui: HTTP 200 UNSUPPORTED/refused; no tool call
else Valid scope and unsupported intent
  id --> ai: HTTP 200 allow + ResolvedScope
  ai -> llm: [HTTP/REST] Classify allowlisted intent
  llm --> ai: UNSUPPORTED
  ai --> ui: HTTP 200 UNSUPPORTED + safe guidance
end

note over ai,rep
Reporting is never called in any refusal branch.
end note

== Design invariants

* Identity online decision is the authorization authority; client/LLM scope is never trusted.
* Reporting tools return canonical aggregate facts, freshness and calculation version.
* DeepSeek cannot call mutation endpoints or arbitrary SQL and receives no raw PII/transaction identity.
* Every final answer/summary is schema-validated; provider failure never becomes invented business data.
* Daily summary revisions are immutable and lineage-preserving; late facts supersede rather than overwrite.
* Outbox/event delivery is at-least-once; consumers deduplicate by event ID/source version.
