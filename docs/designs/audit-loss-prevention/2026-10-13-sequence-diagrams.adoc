== Scope and notation

Các sơ đồ này là design-level diagrams được sinh sau khi user xác nhận 8 flows và participant boundaries. Repository chưa có application implementation source; tên component, queue và endpoint phản ánh Contracts/Architecture, không phải runtime trace.

* L1: system-level flow giữa actor, service, broker, database và storage.
* L2: internal backend flow; Repository/DAO được collapse vào Service → DB.
* `OrderPaid`/Payment revenue facts không được Audit tự suy diễn; Audit chỉ consume approved source facts.
* Audit/Loss Prevention không block Order, Payment, Shift hoặc POS operations.

== Participants

L1 dùng các participant đã xác nhận: Owner/Manager/Cashier, Angular/POS, Order, Promotion, Payment, Shift/POS Device, Identity, EventBridge/SQS, Audit, PostgreSQL, Loss Worker, Case Service và encrypted Object Storage.

== 1. Successful order cancel → audit evidence

=== 1.1 L1 — System Flow

[plantuml]
----

title Order cancel → Audit evidence — L1: System Flow

actor "Manager/POS" as actor
participant "Order Service" as order
queue "EventBridge/SQS" as bus
participant "Audit Service" as audit
database "Audit PostgreSQL" as db

actor -> order: [HTTP/REST] POST /api/v1/orders/{id}/lines/{lineId}/cancel
order -> order: Validate permission, reason, If-Match and order scope
alt Invalid scope/state/reason
  order --> actor: HTTP 403/409/422 safe error
else Valid cancellation
  order -> order: Commit line state + OrderLineCancelled.v1 outbox
  order ->> bus: [EventBridge/SQS] OrderLineCancelled.v1
  bus ->> audit: [SQS async] deliver event
  audit -> audit: Validate, redact and deduplicate sourceEventId
  audit -> db: INSERT immutable audit evidence + projection
  db --> audit: committed evidence/watermark
  audit --> actor: Source command success already returned
end

alt Audit consumer retry/DLQ
  audit ->> bus: [SQS async] retry then DLQ after bounded attempts
end
@enduml
----
