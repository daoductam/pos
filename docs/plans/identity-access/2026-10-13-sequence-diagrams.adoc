== Tổng quan (Overview)

Mô tả ba luồng P0 của `identity-access` theo kiến trúc và hợp đồng đã duyệt. Repository chưa có source code tại thời điểm tạo tài liệu; các sơ đồ này là luồng theo dấu thiết kế (design-traced flow), không phải trace từ controller runtime.

Các luồng bao gồm:

* Kích hoạt lời mời / tư cách thành viên qua Cognito và transactional outbox.
* Quyết định ủy quyền trực tuyến (online authorization decision) qua trạng thái cơ sở dữ liệu chính của Identity DB.
* Thu hồi tư cách thành viên và kiểm chứng yêu cầu kế tiếp bị từ chối ngay lập tức.

== Thành phần tham gia (Participants)

|===
| Tên | Loại | Mô tả

| Client POS/Admin
| Actor
| Client ứng dụng POS hoặc trang quản trị của chủ sở hữu/quản lý/nhân viên.

| Service hạ nguồn
| Service
| Service nghiệp vụ gọi quyết định ủy quyền bằng danh tính workload nội bộ.

| Identity Access API
| Service
| REST API xử lý ngữ cảnh xác thực, tenant/chi nhánh, tư cách thành viên và ủy quyền.

| Identity Worker
| Worker
| Xử lý phân phối lời mời, phát hành sự kiện outbox và thử lại khi gặp sự cố.

| Cognito
| Dịch vụ bên ngoài
| Quản lý OIDC/JWT, phân phối lời mời và vòng đời Cognito subject.

| Identity PostgreSQL
| Cơ sở dữ liệu
| Chân lý nguồn (source of truth) cho ủy quyền tenant, chi nhánh, người dùng và tư cách thành viên.

| EventBridge/SQS
| Message broker
| Phân phối sự kiện ít nhất một lần (at-least-once) tới Audit và các bên tiêu thụ hạ nguồn.

| Audit Service
| Service hạ nguồn
| Tiếp nhận các sự kiện bảo mật/quản trị đã che giấu thông tin; sở hữu hình chiếu truy vấn dài hạn.
|===

== L1 — Luồng Cấp Hệ Thống (System-Level Flow)

[plantuml, identity-access-l1, svg]
----

title Identity & Access — L1: Các luồng hệ thống P0

actor "Client POS/Admin" as client
participant "Identity Access API" as api
participant "Identity Worker" as worker
participant "Cognito" as cognito
database "Identity PostgreSQL" as db
queue "EventBridge/SQS" as bus
participant "Service hạ nguồn" as downstream
participant "Audit Service" as audit

== 1. Lời mời và kích hoạt ==

client -> api: [HTTP/REST] POST /api/v1/tenants/{tenantId}/memberships
api -> api: Xác thực các claim danh tính của JWT
api -> db: Giao dịch: Tạo membership trạng thái INVITED
api -> db: Lưu kết quả idempotency + bản ghi outbox InvitationRequested
db --> api: Commit membership/trạng thái=INVITED
api --> client: HTTP 201 MembershipResponse

api ->> bus: [Sự kiện bất đồng bộ] InvitationRequested.v1
bus ->> worker: [Sự kiện bất đồng bộ] Nhận công việc lời mời
worker -> db: Thu giữ bản ghi InvitationDelivery
db --> worker: Lượt thử phân phối
worker -> cognito: [AWS SDK] Gửi lời mời qua Cognito
cognito --> worker: Nhà cung cấp đã chấp nhận
worker -> db: Đánh dấu phân phối trạng thái SENT

client -> cognito: [OIDC] Hoàn tất lời mời và đăng nhập
cognito --> client: JWT Cognito kèm subject ổn định
client -> api: [HTTP/REST] GET /api/v1/me
api -> db: Phân giải sub → các membership hiện tại
db --> api: Phạm vi tenant/chi nhánh/vai trò đang hoạt động
api --> client: HTTP 200 Ngữ cảnh ủy quyền hiện tại

== 2. Quyết định ủy quyền trực tuyến ==

downstream -> api: [HTTP/REST + mTLS] POST /internal/v1/authorization-decisions
api -> api: Xác thực danh tính workload và phạm vi yêu cầu
api -> db: Đọc trạng thái membership/quyền hạn chính
db --> api: Membership hiện tại và phiên bản
api --> downstream: HTTP 200 cho phép/từ chối + phạm vi có phiên bản

== 3. Thu hồi quyền và từ chối ở yêu cầu kế tiếp ==

client -> api: [HTTP/REST] POST .../memberships/{membershipId}/revoke
api -> db: Giao dịch: Thu hồi (REVOKE) membership
api -> db: Lưu bản ghi outbox MembershipRevoked.v1
db --> api: Commit trạng thái=REVOKED
api --> client: HTTP 200 MembershipResponse đã thu hồi
api ->> bus: [Sự kiện bất đồng bộ] MembershipRevoked.v1
bus ->> audit: [Sự kiện bất đồng bộ] Sự kiện bảo mật đã che giấu
bus ->> downstream: [Sự kiện bất đồng bộ] Vô hiệu hóa cache tùy chọn

downstream -> api: [HTTP/REST + mTLS] Quyết định ủy quyền kế tiếp với JWT cũ
api -> db: Đọc lại trạng thái membership từ cơ sở dữ liệu chính
db --> api: Membership trạng thái REVOKED
api --> downstream: HTTP 200 allowed=false / reason=REVOKED

alt JWT không hợp lệ hoặc workload không đáng tin cậy
  api --> client: HTTP 401 chưa xác thực
  api --> downstream: HTTP 401/403 từ chối
end

alt Cognito hoặc broker không khả dụng
  worker -> db: Duy trì phân phối/sự kiện ở trạng thái có thể thử lại
  worker -> worker: Thử lại theo exponential backoff; thất bại cuối cùng → DLQ/cảnh báo
end

@enduml

title Identity & Access — L2: Luồng nội bộ backend

participant "Controller" as ctrl
participant "Bảo mật / Ngữ cảnh" as security
participant "Application Service" as svc
database "Identity DB" as db
participant "Cognito Adapter" as cognitoAdapter
participant "Worker" as worker
queue "Outbox / Bộ phát sự kiện" as publisher

== Lệnh gửi lời mời (Invitation command) ==

ctrl -> security: Xác thực Cognito JWT / phân giải actor
activate security
security --> ctrl: ActorContext(subject, correlationId)
deactivate security
ctrl -> svc: invite(tenantId, command, actor, idempotency)
activate svc
svc -> svc: Chuẩn hóa email và xác thực chính sách role/branch
svc -> db: SELECT membership của actor + phạm vi chi nhánh đích
db --> svc: Phạm vi ủy quyền hiện tại
svc -> db: BEGIN transaction
svc -> db: INSERT user / membership / delivery
svc -> db: INSERT kết quả idempotency + sự kiện outbox
db --> svc: COMMIT trạng thái INVITED
svc --> ctrl: MembershipResponse(status=INVITED)
deactivate svc
ctrl --> ctrl: Ánh xạ envelope HTTP 201 chuẩn

== Phân phối lời mời của Worker ==

worker -> db: Thu giữ bản ghi InvitationDelivery đang chờ
db --> worker: Bản ghi phân phối
worker -> cognitoAdapter: sendInvitation(delivery)
activate cognitoAdapter
cognitoAdapter --> worker: Đã gửi / lỗi có thể thử lại
deactivate cognitoAdapter
worker -> db: UPDATE trạng thái phân phối và siêu dữ liệu thử lại

== Quyết định ủy quyền nội bộ ==

ctrl -> security: Xác thực danh tính workload
security --> ctrl: WorkloadPrincipal đáng tin cậy
ctrl -> svc: decide(AuthorizationRequest, workload)
activate svc
svc -> db: SELECT membership hiện tại theo sub/tenant/branch
db --> svc: Membership / trạng thái / phiên bản
svc -> svc: Đánh giá quyền hạn và phạm vi chi nhánh
svc --> ctrl: AuthorizationDecision(allow, scope, version)
deactivate svc
ctrl --> ctrl: Ánh xạ phản hồi quyết định

== Thu hồi tư cách thành viên (Revoke membership) ==

ctrl -> security: Xác thực JWT và ngữ cảnh actor
security --> ctrl: Ngữ cảnh Owner / Manager được ủy quyền
ctrl -> svc: revoke(membershipId, reason, expectedVersion, idempotency)
activate svc
svc -> db: SELECT đối tượng đích + bất biến owner
db --> svc: Membership đang hoạt động
svc -> svc: Xác thực phạm vi, bất biến chủ sở hữu cuối và chuyển đổi vòng đời
svc -> db: BEGIN transaction
svc -> db: UPDATE membership SET REVOKED, version+1
svc -> db: INSERT kết quả idempotency + outbox MembershipRevoked
db --> svc: COMMIT
svc --> ctrl: Phản hồi MembershipResponse đã thu hồi
deactivate svc
ctrl --> ctrl: Ánh xạ envelope HTTP 200 chuẩn
svc ->> publisher: Phát hành sự kiện outbox đang chờ

== Yêu cầu kế tiếp sau khi bị thu hồi quyền ==

ctrl -> security: Xác thực claim danh tính của JWT cũ
security --> ctrl: Subject vẫn hợp lệ về mặt mật mã học
ctrl -> svc: decide(subject, tenant, branch, permission)
activate svc
svc -> db: SELECT membership từ trạng thái cơ sở dữ liệu chính
db --> svc: Trạng thái REVOKED
svc --> ctrl: allowed=false, reason=REVOKED
deactivate svc
ctrl --> ctrl: Ánh xạ từ chối mà không làm lộ tài nguyên ngoại lai

alt DB không khả dụng trong lúc đưa ra quyết định được bảo vệ
  svc --> ctrl: DependencyUnavailableException
  ctrl --> ctrl: Đóng lỗi an toàn (Fail closed); HTTP 503 / lỗi chuẩn
end

alt Phân phối trùng lặp phía worker
  worker -> db: Kiểm tra tính ổn định của deliveryId / eventId
  db --> worker: Đã được xử lý trước đó
  worker --> worker: Xác nhận hoàn tất (ACK) mà không gây tác dụng phụ trùng lặp
end

== Ghi Chú Thiết Kế (Design Notes)

* Các claim scope của JWT không được sử dụng làm thẩm quyền ủy quyền; membership trực tiếp được đọc từ Identity PostgreSQL cho các quyết định được bảo vệ.
* API và worker dùng chung các hợp đồng application/domain nhưng có thể mở rộng (scale) độc lập.
* Các chi tiết bên trong của Repository được thu gọn thành luồng `Application Service → Identity DB`; không hiển thị participant repository riêng trong sơ đồ L2.
* Phân phối sự kiện theo cơ chế ít nhất một lần (at-least-once); bắt buộc có event ID / delivery ID ổn định và cơ chế khử trùng lặp ở phía consumer.
